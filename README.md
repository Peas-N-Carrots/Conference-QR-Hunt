# Conference QR Hunt

## About

This app is an icebreaker game for conferences, classrooms, and other networking events. A host will define a set of questions, and users must find a peer who answered yes to each question.

The app also demos an idea I had for sharing data without the client-server architecture that is typical of similar apps like Goosechase or Scavify. QR codes are often used in scavenger hunt style games to verify that you've found a certain checkpoint. This app explores the idea of using QR codes to share data between users too. This allows everything to be statically hosted which is more economical for the host (no server fees), more scalable (no cap on concurrent players), only requires internet to initially load the game (good for public places with spotty internet).

Game data/progress is stored in each app's URL hash, so to store a game to return to later, simply bookmark the page.

## How To Play

Start here to try it out: [Host App][1]

This video briefly explains how to use each app and summarizes the explaination below:

<video src="qr_app_demo.mp4" width="320" height="240" controls></video>

Start by opening the [Host App][1]. Type in a game name and add some personal yes/no questions to the game. Think of things that some but not all of your players might be able to answer yes to (e.g. "Have you been out of the country?" "Are you studying X major?") Make sure to hit the add button to confirm the question. There is an option to remove questions once you've added them if you make a mistake.

Once you've entered a game name and asked at least one question, you may hit the show QR code button to display a QR code that links to the client app.

The [Client App][2] may be accessed directly but won't have any valuable information unless it is accessed from the QR code generated by the host app. When scanning the host app's QR code, you will be taken to a client app that is populated with the same questions from the host. On the profile tab, enter your name and click the check boxes to indicate which items you can answer yes to. Your name and answers are stored in your personal QR code displayed at the top of the page.

On the hunt tab, you will see another list of the same questions with the option to scan for each one. Click this button, enable the camera, and scan another user's personal QR code. If this user is in the same game as you, answered yes to the question, and hasn't already checked off another one of your boxes, they will check off this box for you. If you decide you want to have that person check off a different box, you may remove a checked box after scanning.

Once a client checks off all boxes, they will have their screen locked with a timestamp of when they finished in order to break indicate exactly who finished first.

I (Joe Maloney) originally designed and architected the app as part of some exploration/research into the design of non-network-based data sharing mentioned above. The scripts for the host app were hand coded, but for the sake of time, GitHub Copilot (I believe running GPT-4.0 or Claude Haiku 4.5) was used to write my test cases, model the client app based off of the host app, and complete the styling of the front end.

The following libraries were used in the implementation:
- [lz-string][3]: URL hashing (found on NPM)
- [qrcode][4]: generating personal and game QR codes (found on NPM)
- [html5-qrcode][5]: scanning personal QR codes (found on UNPKG)
